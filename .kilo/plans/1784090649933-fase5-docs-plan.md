   - Type hints obrigatórios em métodos públicos
   - Docstrings Google-style em classes públicas

### T5.3 — ADRs em `docs/adr/`

**Estrutura:** `docs/adr/ADR-001-*.md`, `docs/adr/ADR-002-*.md`

#### ADR-001: Repository Pattern + fallback MySQL → SQLite

**Título:** Adoção de Repository Pattern com fallback offline-first

**Contexto:** O desktop precisa funcionar offline (sem API SerPleno Web) mas também sincronizar quando conectado.

**Decisão:** Introduzir camada Repository entre Services e banco de dados.
- MySQL como fonte primária
- SQLite (via `LocalCache`) como fallback automático quando MySQL falhar
- Decorator `with_local_fallback` intercepta erros de conexão e redireciona para métodos `_local_*`
- `write_with_fallback` grava local + enfileira para sync quando MySQL indisponível

**Consequências:**
- Positivo: Funcionamento offline garantido
- Positivo: Código de serviço não muda quando fonte de dados muda
- Negativo: Complexidade adicional no repository (métodos `_local_*`)
- Negativo: IDs locais negativos precisam ser tratados no sync

#### ADR-002: Injeção de auth via controller (Fase 1)

**Título:** Remoção do acoplamento global de auth_service

**Contexto:** `_auth_service` era estado global em `api.py` e `services/agendamentos.py`, criando acoplamento oculto entre módulos.

**Decisão:** 
- Remover `_auth_service`, `set_auth_service()`, `get_auth_service()` de `api.py`, `mural.py`, `services/agendamentos.py`
- Services recebem `auth_service` via `__init__` (injeção)
- Controllers expõem `auth_service` como propriedade
- `App.iniciar_sistema()` injeta `auth_service` nos controllers

**Consequências:**
- Positivo: Acoplamento explícito, testável
- Positivo: Instanciação de services independente de estado global
- Negativo: `BaseController.__init__` agora recebe `auth_service` opcional
- Negativo: `__getattr__` mantido como deprecated fallback
